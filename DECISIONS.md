## ADR-002 — Hub & Spoke
- **Дата:** 2026-11-18
- **Решение:** принять матрицу дистрибуции «2 языка × 2 скорости»: каноническая карточка + обложка 3:4 в центре; Telegram @t_cortex + Хабр на русском; Substack Notes + Bluesky + Substack Newsletter + точечный Reddit на английском; X исключён.
- **Статус:** активно.

## ADR-003 — KARCAS-DDA
- **Дата:** 2026-11-20
- **Решение:** стандартизировать документацию: единый вход `00_ENTRY.md`, самодостаточные профили `meta/roles/{editor,archivist}.md`, перенос `RUNTIME.md`, `CLAUDE.md`, `docs/WORKFLOW_AND_ROLES.md`, `docs/nova-cortex-portal.md`, `docs/README.md` в `archive/`.
- **Причина:** устаревшие файлы дублировали содержание, увеличивали cold-start LLM-сессии и расходились с реальным состоянием.
- **Статус:** активно.

## ADR-004 — I12 (Минимализм архива)
- **Дата:** 2026-11-20
- **Решение:** отказ от хранения в `records/` и `Handoff`-пакетах полных текстов постов, пересказов статей и информации об обложках. Ввести жёсткий триаж: `MAIA score > 8` → первый эшелон автоматически; иначе — `Artifact Tier A/B/C`.
- **Причина:** карточки 2026-001..003 раздуты дублированием контента (пересказ + копия поста + описание обложки); при выпуске 5 статей/неделя репозиторий становится нечитаемым.
- **Статус:** активно.

## ADR-005 — Операционные правила агентов, разведка Редактора и гейт I12
- **Дата:** 2026-11-20
- **Решение:** закрепить в `meta/agent-rules.md` нумерацию ответов (`MS N`), верификацию дат, формат полных правок, иерархию источников (`I5`) и запрет реконструкции по памяти (`I7`); ввести в `meta/roles/editor.md` делегирование внешней разведки через поисковые нейросети в `Gate 2` и убрать из документации регламентацию доступа Редактора к терминалу; добавить проверку `I12` в `scripts/precommit-checks.sh`. Карточки `2026-001`–`003` сохраняются без изменений (`I1`) как исторические записи `pre-I12`.
- **Статус:** активно.

## ADR-006 — Read-only мост MAIA DB → POST и сквозной ключ maia_id
- **Дата:** 2026-11-20
- **Решение:** внедрить скрипт `scripts/get-digest.sh` для прямого read-only извлечения структурированных дайджестов (`Gate 1`) и полных аннотаций (`Gate 2`) из PostgreSQL `maia-db` без изменения кода `MAIA` и `n8n`; добавить обязательный внешний ключ `maia_id` (`incoming_messages.id`) в `meta/handoff-protocol.md` и `templates/record-template.md`.
- **Статус:** активно.

## ADR-007 — Фактологический Hub (I12), мягкий приоритет score > 8 и разметка DIGEST_TRIAGED
- **Дата:** 2026-11-21
- **Решение:** согласовать `EDITORIAL_POLICY.md` §5 с `I12` (карточка в `records/` хранит только фактологическое ядро; тексты постов и обложки в публичном репо не хранятся и при необходимости выносятся в отдельный приватный репозиторий-сейф); перевести `MAIA score > 8` в статус приоритетного допуска с утверждением Архитектора; ввести обязательную разметку всех 15 позиций дайджеста (`DIGEST_TRIAGED`) в `logs/events.jsonl` для калибровки скоринга `MAIA`.
- **Статус:** активно.

## ADR-008 — Clean slate, протокол Редактор → Копирайтер, минимальная архитектура
- **Дата:** 2026-11-22
- **Решение:** (1) удалить legacy-карточки `records/2026/001..003` (история сохранена в git log, I1 к ним больше не применяется — они не в рабочем дереве); (2) принять протокол «Редактор → Копирайтер» как рабочее соглашение (не инвариант): разделение «веб-разведка + технический черновик» (Редактор, `Gate 1–Gate 3`) и «адаптация под широкого читателя + генерация обложки» (Копирайтер); (3) минимальная архитектура для запуска конвейера — без портала, без crosswalk, без backfill.
- **Причина:** роли разделены из-за разных сильных сторон LLM: поисковые модели дают технически точный черновик, но плохо адаптируют под широкого читателя; визуальные/копирайтерские модели наоборот.
- **Статус:** активно.

## ADR-009 — TRIAGE_LOG как отдельный файл и версия оценщика
- **Дата:** 2026-11-22
- **Решение:** вести `logs/triage.jsonl` (append-only) — одна строка на каждую из 15 позиций дайджеста (ключи: ts, digest_date, digest_pos, maia_id, arxiv_id, score, scorer, decision, reason_code, record_id, actor, note≤120). Закрытый список reason_code согласован с EDITORIAL_POLICY §2. Порог `score > 8` прежний, калибровка — по накопленным данным. Поле `scorer` зарезервировано: в схеме `maia-db` отсутствует, пишется `—` до появления.
- **Начало накопления:** 2026-11-19 (пилот `maia_id 484476` в Git не занесён).
- **Статус:** активно.
