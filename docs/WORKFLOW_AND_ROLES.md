# POST — Workflow & Roles (model-agnostic)

Регламент трёх ролей в контуре POST / Nova Cortex (ядро MAIA).
Model-agnostic: любая LLM-модель может занимать любую из трёх ролей при соблюдении контрактов.

---
## 1. Роли

### Архитектор (человек)
- стратегический отбор тем, утверждение текстов;
- санкция публикации и `git push`;
- передача пакетов между чатами и запуск команд в терминале.

### Редактор POST (Gate 1–Gate 3), любая LLM
- триаж дайджестов `MAIA`;
- кластеризация и утверждение выбора статьи;
- Барьер истинности: `[FACT]`, `[HYPOTHESIS]`, `[UNKNOWN]`;
- фолбэк по скриншоту при блокировке arXiv;
- тексты под площадки, 2-шаговое согласование и генерация обложек 3:4;
- на выходе — только `PAYLOAD`, без shell-кода.

### Архиватор POST (Gate 4), любая LLM
- разведка состояния репозитория;
- приём `PAYLOAD`;
- ведение `records/`, документации и `logs/events.jsonl`;
- проверка инвариантов I1–I11;
- генерация безопасных скриптов и команд обновления в git;
- отчёт в формате `ОТЧЁТ АРХИВАТОРА POST → РЕДАКТОРУ POST`.

---

## 2. Протокол входа новой LLM-сессии (Onboarding)
Постоянный порядок чтения перед началом работы:
1. `README.md` — точка входа, навигация.
2. `RUNTIME.md` — актуальное состояние.
3. `EDITORIAL_POLICY.md` — редакционный стандарт.
4. `docs/WORKFLOW_AND_ROLES.md` — этот файл (роли и контракты).
5. `INVARIANTS.md` — обязательно для Архиватора.

Правило: ни одна роль не начинает работу без прочтения всех пяти документов.

---

## 3. Связь ролей с цепочкой действий
- Редактор не пишет shell-код в чат редактора.
- Архиватор не производит коммиты за редактора.
- Архиватор не производит `git push` без явной санкции Архитектора.
