# Nova Cortex Portal — спецификация View Layer

Статический агрегирующий слой поверх актуальных репозиториев с ядром MAIA.
Портал — только чтение и агрегация; источники истины остаются в репозиториях.

---

## Архитектура
```
POST repo (records/, docs/, logs/)
        │
        ▼  Git Push / repository_dispatch
  Build Hook (фильтр I4)
        │
        ▼
  Static Site (Cloudflare Pages / GitHub Pages)
        │
        ▼
  View Layer (read-only)
```

- Триггер: push в `origin/main` или `repository_dispatch`.
- Фильтр `I4`: на этапе сборки проверятся секреты, пути, персональные данные.
- Публикация — только после успешного фильтра.

---
## Разделы сайта

### `/` — Главная
- Манифест экосистемы с `MAIA` в ядре.
- Карта репозиториев и ссылки на `records/`.

### `/post` — Публикации POST
- Режим «Атом»: одна карточка + обложка 3:4 + ссылки на площадки.
- Режим «Тематическое досье»: кластер карточек по теме.

### `/systems` — Системы экосистемы
- Активные репозитории, их роли и связи.
- Ядро: `MAIA`; активный контур: `MAIA`, `POST`.

### `/lab` — Эксперименты
- Черновые и исследовательские материалы (не публикации).

### `/audit` — Аудит
- Публичный доступ к `logs/events.jsonl` в читаемом виде.
- Проверка `I1`: append-only журнал доступен для верификации.

### `/llms.txt` — Машиночитаемая навигация
- Структурированный индекс для LLM-агентов.
- `View Raw .md` — прямая ссылка на исходный маркдаун карточки без рендера.

## Открытые вопросы для MAIA (кросс-анализ)

1. **Источник агрегации:** должен ли портал читать только `POST` или агрегировать все активные репозитории контура?
2. **Формат манифеста:** какой контракт данных между ядром `MAIA` и View Layer (структура индекса, версионирование)?
3. **Кэширование и инвалидация:** стратегия пересборки при push в любой из репозиториев (точечно vs. полная)?
4. **Публичность аудита:** какие события из `logs/events.jsonl` показывать в `/audit`, а какие оставить внутренними?

Ответы фиксируются отдельным архитектурным решением и отражаются в этом документе (редактируемо, не I1).
